# `docs/` DOX

## Purpose

Architecture notes, roadmap items, and test guidance for the project.

## Ownership

- Architecture docs in `docs/architecture/`
- Test guidance in `docs/testing/` and `docs/tests/`
- Engineering roadmaps in `docs/engineering/`

## Local Contracts

- Keep docs aligned with the codebase and current roadmap.
- Prefer concise, operational documentation over long-form narrative.

## Work Guidance

- Update docs when workflows, native behavior, or testing expectations change.
- If a doc is about a shipped contract, keep it current with the implementation.

## Verification

- Manual review against the code paths the doc describes

## Child DOX Index

- `docs/architecture/` - app architecture and bridge design.
- `docs/engineering/` - roadmap and implementation notes.
- `docs/testing/` - test process notes.
- `docs/tests/` - test authoring guidance.
